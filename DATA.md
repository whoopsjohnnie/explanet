# ExPlanet — where the data lives

**This repository holds the engine and the world-building tools only.** No
world data and no seed data are committed. Everything data-shaped lives in
the world database or in S3 (and the tools here know to say so when a seed
file is missing).

## The world database (source of truth for worlds)

Your PostgreSQL server — set `PGHOST`, `PGDATABASE`, `PGUSER` env vars. This
repository ships **no** infrastructure names: hosts, database names, users
and credentials belong in your shell env / secret manager, never in code,
docs or commit messages. Schema: `explanet`. DDL: `db/schema.sql` +
`db/migrations/`. Password: `PGPASSWORD` or `~/.pgpass`.

| table     | contents                                                       |
| --------- | -------------------------------------------------------------- |
| `worlds`  | one row per world document (name, gravity, scale [meters per world unit], version) |
| `bodies`  | per-body documents (orbit, spin, presets, rings/scripts/kind/atmosphere/generation) |
| `atoms`   | hex cell elements — the atom model, one row per cell chunk     |
| `stars`   | real-sky reference catalog (Yale BSC v5, `BSC5`, 9,096 rows)   |
| `materials` | material palette rows                                      |

The app never reads files for worlds: the browser talks to `/api` (dev:
vite middleware, prod: `server/serve.mjs`), and `/api` talks to postgres.

## S3 seeds bucket (inputs for the world-building tools)

Generation seed files are vendored in S3 under a bucket referred to below
as `s3://explanet-seeds/`, keyed by their repo-relative path, so a fetch is
a one-liner and lands files exactly where the tools expect them:

```sh
aws s3 sync s3://explanet-seeds/ .
```

| seed file                            | what it is                                   | can also be regenerated by                          |
| ------------------------------------ | -------------------------------------------- | --------------------------------------------------- |
| `scripts/stars/data/BSC.json`        | Yale Bright Star Catalog v5 (public domain)  | mirrored in the `stars` table; re-export from source |
| `scripts/sol-real/data/moons.json`   | scraped moon catalog (NASA)                  | `scripts/sol-real/fetch-moons.mjs`                  |
| `scripts/sol-real/data/orbits.json`  | scraped asteroid/comet osculating elements   | `scripts/sol-real/fetch-small.mjs`                  |
| `scripts/sol-real/data/land-50m.json`| world-atlas 1:50m land TopoJSON (Earth)      | re-download from the world-atlas distribution        |

All seed reads go through `scripts/seed.mjs`, which fails with a pointer to
this file instead of a stack trace.

## Generated artifacts (gitignored, regenerated on demand)

| file                     | how to regenerate                          |
| ------------------------ | ------------------------------------------ |
| `public/world.json`      | `npm run gen:world` (from `core/starter.js`) |
| `public/sol-real.json`   | `node scripts/gen-sol-real.mjs` (needs the seeds above) |
| `src/core/starCatalog.js`| `npm run gen:stars` — **tracked in git** (the app bundles it); regenerated from the BSC seed |

`world.json` remains the *file format* for import/export (drag-&-drop,
Save/Open in the app) and for `scripts/import-db.mjs` — it is just never
committed. To load the demo system into the database:
`npm run gen:world && npm run db:import`.

## Rules for contributors

1. Never commit a world document, world export, or seed data file. If a
   tool needs data, it reads the DB, a `scripts/**/data/` seed (fetched
   via `scripts/seed.mjs`), or the starter generator.
2. Never commit infrastructure identifiers — hostnames, database names,
   users, credentials, URLs. Tools read `PGHOST`/`PGDATABASE`/`PGUSER` and
   fail with a clear message when they are unset.
3. New seeds get added to the bucket, listed in the table above, and read
   through `readSeed()`.
4. Large generated *source* the app bundles at build time (like
   `starCatalog.js`) may be tracked — keep those under ~200 KB.
